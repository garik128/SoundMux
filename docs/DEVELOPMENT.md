# SoundMux

Windows-приложение для добавления внешней озвучки к фильму. Этап B: реальная обработка через Tauri + Rust, локальный Python/NumPy, FFprobe, FFmpeg и mkvmerge. Браузерный просмотр остаётся отдельным демонстрационным режимом.

## Запуск текущей сборки

Дважды нажмите **«Запустить SoundMux.cmd»** в корне проекта. Он открывает `src-tauri/target/debug/SoundMux.exe`. Node.js, Rust и системный Python для этого запуска не используются. Нужны созданный локальный runtime `.runtime`, конфигурация `.local/tools.json` и установленные в ней пути к медиакомпонентам. Это сборка для разработки на текущем компьютере. Портативная поставка для другого компьютера собирается отдельно, см. раздел «Портативная сборка».

В браузере по адресу http://127.0.0.1:5174 работает только демо: пути к локальным файлам Windows и реальная обработка доступны в окне приложения. Кнопка «Открыть демонстрацию» в подвале приложения включает явную демонстрацию, без создания файла. Выбор настоящего файла возвращает реальный режим и убирает несовместимые демо-источники.

В шестерёнке «Настройки» доступны тема («Как в системе» по умолчанию, светлая и тёмная), акцентный цвет (янтарный по умолчанию, красный, синий, зелёный), начальная громкость плеера, умолчания для новой озвучки (язык, название дорожки или галочка «брать из имени файла озвучки» (включена по умолчанию), включение по умолчанию, сохранение исходного звука и озвучки, режим обработки; подставляются при каждом запуске). Название дорожки для конкретного фильма видно и правится на главном экране рядом с названием результата: пока вы его не меняли, оно следует за файлом озвучки и настройками (по умолчанию это имя файла озвучки без расширения); смена файла озвучки возвращает значение по умолчанию. Пустое поле означает название по умолчанию, нагрузка на процессор при пересчёте звука (быстро, умеренно, фоном; сохраняется в `settings.json` в папке настроек программы и передаётся воркеру как `load`), папка временных файлов и очистка кэша. По умолчанию кэш лежит в папке `cache` рядом с программой (в отладочной сборке `.local/cache`); если туда нельзя писать, используется кэш пользователя в `%LOCALAPPDATA%`. Выбранная вами папка получает вложенную папку `SoundMux cache`, прежние временные файлы автоматически не удаляются. Значения сохраняются автоматически. Очистка доступна после завершения обработки и удаляет только опубликованные фрагменты и подготовленный звук, без исходников и результатов. Автоматического ограничения размера кэша пока нет. Фон однотонный.

Размер, положение и развёрнутое состояние окна сохраняются при закрытии и восстанавливаются при следующем запуске. Последние папки фильма, озвучки и результата запоминаются отдельно, в том числе после перезапуска. Для первой озвучки предлагается папка последнего фильма; если сохранённая папка исчезла, используется доступная предыдущая папка или стандартное окно выбора.

Настройки окна и история папок хранятся в пользовательском каталоге конфигурации приложения. Служебный идентификатор оставлен прежним, чтобы переименование в SoundMux не сбросило существующий профиль. Выбранная ранее тема также переносится.

## Быстрая проверка интерфейса без настоящего фильма

В `.local/smoke` подготовлены маленькие синтетические файлы:

1. Фильм — `Синтетический фильм [96 с].mkv`.
2. Озвучка — `Синтетическая озвучка +1 с.wav`.
3. «Проверить синхронизацию»: ожидается, что звук позже примерно на 1 секунду; предлагается отрицательная задержка, чтобы включить его раньше.
4. Сравните исходный и исправленный звук в начале, середине и конце. Воспроизведение синтетического шума проверяет работу плеера; это не настоящий фильм.
5. «Сохранить фильм» создаёт отдельный `.NEW.mkv` рядом с тестовым фильмом. Если имя занято, предлагаются «Изменить имя», «Отмена» и «Перезаписать». Анализ и ручные поправки сохраняются; после смены имени можно сразу повторить сохранение. Перезапись требует отдельного подтверждения для конкретного существующего файла.
6. Для отмены запустите проверку или сохранение и нажмите «Отменить». Повторный запуск должен работать с теми же источниками.

Программа выбирает оригинальную звуковую дорожку для сравнения, избегая комментария режиссёра. В «Дополнительно» можно изменить звук для сравнения и выбрать нужный звук из внешнего файла с несколькими дорожками. Смена этих настроек сбрасывает анализ, но сохраняет введённое имя результата и ручную поправку. Ошибка сохранения истории папок не блокирует выбор файла.

В «Дополнительно» под каждым сложным полем стоит одна короткая строка, а подробности открываются по значку «?» в карточке (закрывается по Esc, клику в стороне и прокрутке). Карточка рисуется поверх окна отдельным слоем (`src/components/InfoHint.tsx`, стили в `src/styles/hint.css`), так что её можно подключать к любой настройке.

## Реальная обработка и сохранность файлов

- FFprobe читает реальные метаданные. Отсекаются пустые, недоступные файлы и файлы с нулевым началом. Это предварительная проверка, она не гарантирует полной загрузки торрента: повреждения в середине могут обнаружиться только при обработке. Имя, размер и время изменения защищают от использования анализа после изменения источника.
- Анализатор — неизменённый снимок существующего `audio_sync.py`. Полный запуск декодирует оба файла целиком (для фильма в десятки гигабайт это около минуты и больше, упирается в диск). Поэтому для фильмов от 10 минут сначала работает быстрая проверка `backend/quick_analysis.py`: она вызывает те же функции анализатора, но звук фильма читает только в семи сравниваемых окнах (с перемоткой), а файл озвучки целиком. Результат (вердикт, сдвиг, скорость, смещения по окнам) совпадает с полным запуском; при любой неудаче (звук закончился раньше, ошибка перемотки, короткий файл) выполняется полный анализ. Защита от ложного дрейфа отдельно проверяет отношение длительностей с допуском `.002 + abs(offset_ms) / 1000 / reference_duration`. При отклонении автоматическая коррекция не применяется.
- Способ изменения скорости выбирается в «Дополнительно» → «Скорость и тон» (по умолчанию «Автоматически», главный экран не меняется). В «Автоматически» звук ресемплируется вместе с тоном (`asetrate` + `aresample`) только там, где тон на слух не меняется: измеренная скорость совпадает с переходом 24 ↔ 23,976 кадр/с (допуск 0,03%), и тогда берётся точное соотношение. Способ обратим и без артефактов растяжки. Для всего остального, включая PAL (25 кадров/с, разница 4%), тон сохраняется, как было раньше. Пункт «Менять скорость вместе с тоном» включает ресемплирование принудительно (для 25, 23,976 и 24 кадр/с со скоростью по точному соотношению), «Сохранять тон» запрещает его; смена пункта повторяет проверку. Если проверка с точным соотношением не прошла, пробуется измеренная скорость, так что результат не хуже прежнего. Выбранный способ показан в «Дополнительно» и под плеером. Правила и допуски: `backend/media.py` (`FILM_RATES`, `standard_ratio`, `resolve_pitch`).
- Сохранение тона: Rubber Band. Rubber Band работает в один поток (около 8x реального времени), поэтому длинная дорожка (от 10 минут) режется на части по 4 минуты с запасом по краям, части обрабатываются параллельно (до 8 процессов с пониженным приоритетом) и склеиваются кроссфейдом 0,5 с; длина каждой части и итога проверяется, при расхождении сборка останавливается. Интерфейс показывает проценты и оценку оставшегося времени (по замеру на этой машине, затем по фактической скорости). Код: `backend/tempo.py`. Ресемплирование с тоном работает быстро и на части не режется. После этого звук анализируется ещё раз. Неуверенный результат и другой монтаж требуют явного подтверждения сохранения.
- Положительная задержка включает внешнюю озвучку позже. Порядок: скорость, затем автоматическая + ручная задержка. Отрицательный сдвиг AC3/E-AC3 округляется до аудиокадра; предпросмотр и сборка используют одну эффективную задержку.
- Настоящий предпросмотр — H.264/AAC MP4 до 20 секунд, 1280x720 (достаточно, чтобы сверять звук по губам). Плеер разворачивается на весь экран кнопкой, двойным щелчком по картинке или одноимённой кнопкой; в полноэкранном режиме остаются выбор звука, подстройка сдвига («− Звук раньше», «＋ Звук позже»), пауза пробелом и выход по Esc. Звук фильма берётся из того же перемотанного входа, что и картинка, поэтому подготовка не читает весь файл. Он сохраняет абсолютное положение сцены после коррекции скорости, сдвига, добавления тишины и обрезки. Переключение вариантов сохраняет сцену, старый фрагмент не воспроизводится как актуальный. Фрагменты и полный исправленный звук кэшируются (папка кэша описана в разделе про настройки); очистка доступна в настройках. HDR10, HLG и Dolby Vision с базовым слоем HDR10 в предпросмотре переводятся в SDR (BT.709) тонмаппингом Hable: кадр сначала уменьшается до 720p, затем `zscale` и `tonemap` работают уже на маленьком кадре, поэтому подготовка почти не замедляется. Это только предпросмотр: видео в результате копируется без перекодирования и цвета не меняет. Dolby Vision Profile 5 (без слоя HDR10) показывается с искажёнными цветами.
- Видео копируется. При изменении скорости звук кодируется тем же форматом и с тем же битрейтом, что в исходной озвучке (AC3, E-AC3, AAC; DTS превращается в E-AC3), а для остальных форматов создаётся FLAC. В режиме для старых телевизоров — E-AC3. Для более шести каналов совместимый режим отказывается от преобразования, чтобы не выполнять незаметное сведение в 5.1. Пересчёт не сохраняет дополнительные данные Atmos/DTS:X.
- Вторая озвучка добавляется повторным проходом: после сохранения кнопка «Добавить ещё озвучку» берёт готовый файл как фильм (звук для сравнения остаётся тем же по названию), результат получает имя `.NEW2`, `.NEW3` и не затирает предыдущий. Первый результат остаётся на диске.
- Озвучка в виде «голого» потока Blu-ray (`.thd+ac3`, `.thd`, `.mlp`) принимается наравне с остальными. FFmpeg читает такой файл как одну сломанную дорожку AC3, а mkvmerge видит обе настоящие (TrueHD с Atmos и AC3 5.1). Поэтому при выборе файла mkvmerge без перекодирования копирует дорожки в `unpacked-<хэш>.mka` в папке кэша (около 30 секунд и столько же места, сколько занимает файл; повторно не делается, после очистки кэша создаётся заново), и дальше работа идёт с этой копией. Исходный файл не меняется. В «Дополнительно» → «Какую озвучку взять из файла» дорожки подписаны кодеком и раскладкой каналов («TrueHD Atmos 7.1», «AC3 5.1»); выбранная дорожка попадает в результат как есть, без пересчёта. Распаковка включается, только если mkvmerge нашёл больше дорожек, чем FFmpeg, или FFmpeg не смог прочитать частоту дискретизации; обычные файлы не затрагиваются.
- mkvmerge по умолчанию сохраняет все субтитры с их default/forced-флагами; в «Дополнительно» ненужные субтитры и звуковые дорожки фильма можно снять галочкой (настройки `skipSubtitles` и `skipAudio`, действуют только на текущий фильм). Главы, вложения и, по настройке, исходный звук. Исправленная новая озвучка идёт первой среди звуковых дорожек; её нетронутая копия добавляется согласно настройке.
- До сборки оценивается свободное место. Запись идёт в собственную временную папку на выходном диске. После проверки состава, флагов, длительности и читаемости конца файл переименовывается в окончательный. Существующий результат заменяется только после явного подтверждения и успешной проверки нового: при ошибке или отмене предыдущий результат остаётся нетронутым. Если существующий файл изменился после подтверждения, подтверждение запрашивается заново. Исходные фильм и озвучку нельзя перезаписать даже с подтверждением. Эти проверки не являются проверкой каждого кадра.
- Rust запускает worker без shell и включает его в Windows Job Object до начала обработки. Отмена завершает Python и всех потомков, ожидает их завершения и удаляет временные каталоги задачи. Источники не удаляются и не меняются.
- Проценты подготовки звука, сборки и фрагментов берутся из вывода FFmpeg/mkvmerge. Для анализа без измеримого процента показывается текущий этап.

## Устройство и технологии

**Из чего собрано**

| Слой | Технологии | Где |
|---|---|---|
| Интерфейс | React 19, TypeScript 5.9, Vite 7, обычный CSS без UI-библиотек | `src/` |
| Оболочка | Tauri 2 (Rust), плагины dialog и window-state, `windows-sys` для Job Object | `src-tauri/src/` |
| Обработка | Python 3.12 (встроенный) и NumPy; вызывает FFmpeg, FFprobe, mkvmerge | `backend/` |
| Сравнение звука | `backend/vendor/audio_sync.py`: неизменный снимок готового анализатора | `backend/vendor/` |
| Внешние программы | FFmpeg с фильтром Rubber Band, FFprobe, MKVToolNix (mkvmerge) | `bin/` в поставке |

Точные версии зависимостей закреплены в `package-lock.json` и `src-tauri/Cargo.lock`; версии Python, FFmpeg и mkvmerge можно посмотреть командами `--version` из `.local/tools.json`.

**Как идёт работа**

1. Интерфейс вызывает команду Rust `media_run` (`probe`, `analyze`, `preview`, `build`). Для каждой задачи Rust запускает отдельный процесс Python `backend/worker.py` без shell, помещает его в Windows Job Object и передаёт запрос одной строкой JSON в stdin. Ответы идут строками JSON в stdout: события `progress`, затем `result` или `error`. Обе стороны явно используют UTF-8.
2. Отмена, закрытие окна и ошибка завершают весь Job Object: Python, FFmpeg и mkvmerge останавливаются вместе, временная папка задачи удаляется.
3. `backend/media.py` (`Pipeline`) содержит всю работу с файлами. `backend/tempo.py` отвечает за параллельный пересчёт скорости. Python-код никогда не пишет в исходные файлы.

**Алгоритмы**

- Сравнение: оба звука приводятся к моно 8 кГц, строится огибающая всплесков 1 кГц и считается взаимная корреляция в 7 окнах по файлу. Линейная подгонка «сдвиг от времени» даёт постоянную задержку и коэффициент скорости. Для длинных фильмов окна читаются перемоткой, а не декодированием всего файла (`quick_analysis.py`). Сверху стоят свои проверки: правдоподобие отношения длительностей, остаточное расхождение, обязательная повторная проверка на уже исправленном по скорости звуке. Неуверенный результат не применяется молча.
- Декодирование озвучки AC3/E-AC3 идёт с `-drc_scale 0` (`tempo.DECODE`): иначе FFmpeg применил бы к звуку динамическую компрессию из потока, и она осталась бы в пересчитанной дорожке. Тот же ключ стоит в предпросмотре. Приведение к 48 кГц для AC3/E-AC3 и ресемплирование с тоном делает SoX (`resampler=soxr`, если он есть в сборке FFmpeg).
- Громкость: после пересчёта (скорость или режим для телевизоров) сборка измеряет пик (`volumedetect`). Если звук упирается в 0 дБ (порог -0,1 дБ), показывается предупреждение о возможных щелчках. Галочка «Защита от перегрузки» в «Дополнительно» вместо предупреждения пересчитывает дорожку на 3 дБ тише. Звук без пересчёта не затрагивается. Версия правил пересчёта (`AUDIO_RENDER_VERSION`) входит в ключ кэша: при её смене старый кэш не используется.
- Скорость с сохранением тона: Rubber Band (`rubberband=tempo=…`). Длинная дорожка режется на части по 4 минуты, к каждой добавляется по 3 секунды разгона с обеих сторон (после рендера отбрасываются), части рендерятся параллельно и склеиваются кроссфейдом 0,5 с. Число процессов задаётся режимом нагрузки в настройках (до 8).
- Задержка: в mkvmerge через `--sync`, без перекодирования. Отрицательный сдвиг AC3/E-AC3 округляется вниз до целого аудиокадра (1536 отсчётов); предпросмотр и сборка используют одно и то же эффективное значение.
- Предпросмотр: клип до 20 секунд, видео 1280x720 H.264 (`libx264`, `veryfast`, CRF 23; HDR предварительно приводится к SDR), звук AAC 192 кбит/с. Полная дорожка с учётом скорости рендерится до выбора сцены, поэтому абсолютное время, тишина и обрезка совпадают с итогом. Клипы и подготовленный звук кэшируются по SHA-256 от всех параметров, которые на них влияют.
- Сборка: mkvmerge берёт видео, субтитры, главы и вложения фильма без изменений, добавляет новую озвучку (и по настройке исходную), ставит нужные флаги default и порядок дорожек. Результат пишется во временную папку на выходном диске, проверяется (состав дорожек, флаги, главы, вложения, длительность, читаемость последних секунд) и только затем переименовывается в окончательное имя.

**Форматы звука в результате**

Без изменения скорости звук копируется как есть. При изменении скорости сжатая озвучка (AC3, E-AC3, DTS, AAC) остаётся сжатой с тем же битрейтом (не выше 640 кбит/с для AC3, 1024 для E-AC3 и DTS, 512 для AAC), остальные форматы переводятся в FLAC; режим для старых телевизоров кодирует E-AC3 (до 6 каналов, 448 кбит/с для стерео и 1024 кбит/с для 5.1). Дополнительные данные Atmos и DTS:X при пересчёте не сохраняются.

**Хранение данных**

- Журнал: `logs` рядом с программой (в отладочной сборке `.local/logs`; если рядом писать нельзя, папка журнала в пользовательском каталоге). Одна короткая строка на событие: начало и конец анализа, сборки и открытия файла (имена файлов, размеры, дорожки, настройки, вердикт и скорость), ошибки с командой, кодом выхода и концом вывода (не больше 4000 символов), заметные решения (распаковка `.thd+ac3`, защита от перегрузки, неудачная проверка скорости), запуск программы и сбои, о которых воркер сам сообщить не смог. Предпросмотры пишутся только при ошибке. Время везде по UTC. Профиль пользователя заменяется на `%USERPROFILE%`. Ротация: `soundmux.log` закрывается на 256 КБ и становится `soundmux.1.log`, затем `soundmux.2.log`, самый старый стирается, то есть журнал не занимает больше примерно 750 КБ. Пишут и Python (`backend/applog.py`), и Rust (`src-tauri/src/applog.rs`) в одни файлы с одинаковым правилом; ошибка записи никогда не ломает работу. Папка открывается в настройках кнопкой «Открыть папку журнала»; `diagnose.bat` в портативной версии печатает последние строки журнала.
- Кэш: `cache` рядом с программой, либо выбранная в настройках папка, либо запасной вариант в пользовательском каталоге; при очистке удаляются только файлы с именами-хешами: фрагменты предпросмотра `<хеш>.mp4`, пересчитанный звук `audio-<хеш>.<расширение по кодеку>` (flac, ac3, eac3, mka) и распакованные дорожки `unpacked-<хеш>.mka`. Всё это создаётся заново при необходимости.
- Настройки: `settings.json` (папка кэша и нагрузка) и `dialog-history.json` (последние папки) в каталоге конфигурации приложения; тема, цвет, громкость и умолчания новой озвучки в `localStorage` окна. Умолчания хранятся с версией формата и только в части, изменённой пользователем: так более старые значения не закрепляют настройку, которую никто не выбирал, а смена заводских значений при обновлении доходит до всех, кто их не трогал. Кэша файлов интерфейса в профиле нет (интерфейс встроен в EXE). Файлы настроек пишутся атомарно (запись рядом и переименование).
- Служебный идентификатор приложения `local.audiomost.desktop` оставлен от прежнего названия, чтобы не терять профиль.

**Структура проекта**

```
src-tauri/src/       Rust: main (задачи, Job Object), settings, preferences, cache, jobs, shell, applog (журнал)

```

## Разработка и проверки

```powershell
npm ci
npm run dev
npm run build
npm test
npm run test:media
npm run check:native
npm run test:native
npm run desktop
```

После правок, которые попадают в приложение, портативная версия и архив пересобираются (`scripts/package-portable.ps1`, см. «Портативная сборка»); перед этим не должен быть запущен `SoundMux.exe` из `dist-portable`, иначе Windows не даст заменить файл. Правило записано в `CLAUDE.md`.

`npm run dev` (демо в браузере на 127.0.0.1:5174) нужен только разработчику. `vite.config.js` исключает из наблюдения папки сборок, инструментов и тестовых фильмов: иначе на Windows дескрипторы наблюдателя Node не дают Проводнику удалить или переименовать свежераспакованную копию внутри проекта (Проводник при этом пишет про права администратора). Перед удалением таких папок сервер всё равно можно остановить. `npm run desktop` собирает фронтенд и native EXE, затем запускает окно. Перед пересборкой закройте ранее запущенный `SoundMux.exe`. `scripts/desktop.ps1 -Build` только собирает, `-Check` проверяет Rust. Rust находится в `.tools/cargo` и `.tools/rustup`, системный PATH не менялся. Зависимости закреплены `package-lock.json` и `src-tauri/Cargo.lock`.

Для воспроизведения окружения разработки на другом компьютере нужны Node.js, MSVC C++ Build Tools и WebView2; Rust устанавливается отдельно из официального источника с профилем minimal. Локальный Python runtime и конфигурацию можно подготовить `scripts/prepare-runtime.ps1`, передав `-PythonRoot`, `-FfmpegDirectory` и `-Mkvmerge`. Скрипт ничего не устанавливает в систему и отказывается перезаписывать существующий runtime. Папки `.runtime`, `.tools` и `.local` не включаются в исходный код.

Автопроверки используют только небольшую синтетику с апериодическими всплесками. Проверяются оба направления задержки, PAL/NTSC и малый дрейф, ложный дрейф, другая заставка, повторная проверка скорости, сохранение потоков и флагов, отказ при нехватке места и существующем результате, и совпадение предпросмотра с итогом в трёх местах. Отдельный Rust-тест проверяет завершение дерева процессов. Способы изменения скорости проверяются на синтетических тонах: длина и частота при ресемплировании с тоном и при растяжке с сохранением тона, точная скорость для перехода 24 ↔ 23,976, AC3 44,1 кГц на выходе 48 кГц тремя способами, защита от перегрузки, отключение сжатия динамики при декодировании, очистка кэша любых расширений (Rust). Параллельный рендер скорости проверяется на синтетике с уменьшенными порогами: длина, сдвиг, уровень на швах, очистка временных частей и отказ при неполной части. Тесты создают временные папки с кириллицей, пробелами и скобками, затем убирают их. Реальные пользовательские фильмы не используются.

Дополнительно проверяются сохранение независимой истории папок после повторного чтения настроек и восстановление после повреждённого файла настроек. Запрос с кириллицей, японскими символами и акцентами проходит через настоящий JSON stdin/stdout worker: обе стороны явно используют UTF-8, независимо от системной кодовой страницы Windows.

## Что ещё не готово

Установка с подписью издателя, автономный WebView2 для старых систем и обновление программы. ## Портативная сборка

`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package-portable.ps1` собирает релизный EXE (статический CRT, встроенный интерфейс) и папку `dist-portable/SoundMux` с Python, FFmpeg, FFprobe, mkvmerge, бэкендом, лицензиями и `README.txt` для получателя, затем `dist-portable/SoundMux-portable.zip` (около 160 МБ). Архив пишется через .NET `ZipArchive`, а не `Compress-Archive`: тот в Windows PowerShell 5.1 сохраняет пути с обратными слэшами, и распаковщики Linux и macOS превращают их в плоские файлы с `\` в имени. После записи скрипт читает архив обратно и падает, если какое-то имя содержит `\`, лежит вне `SoundMux/` или число файлов не совпадает с папкой. Ключ `-NoZip` пропускает архив. Для запуска нужны 64-битная Windows 10/11 и WebView2. Основной `mkvmerge.exe` (MKVToolNix 100) статически требует `SetThreadDescription` и ещё несколько функций, которых нет в самых ранних сборках Windows 10 (подтверждено на 10.0.14393). Поэтому рядом лежит запасной `bin/legacy/mkvmerge.exe` (MKVToolNix 60.0.0, происхождение и контрольные суммы в `.tools/mkvtoolnix-60.0.0/SOURCE.txt`, ключ `mkvmergeLegacy` в `.local/tools.json`). `Pipeline.working_mkvmerge` берёт первый из: основной, запасной, установленный MKVToolNix (PATH, Program Files); подходит только тот, что запускается и умеет JSON-идентификацию, а название ключа «дорожка по умолчанию» (`--default-track-flag` или старое `--default-track`) определяется по справке. Если не подошёл ни один, причина объясняется ещё при проверке звука. установка и права администратора не нужны. Комплект не подписан, SmartScreen покажет предупреждение. Размер и состав смотреть командой скрипта, а не в этом файле.
